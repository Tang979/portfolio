Event-Driven Communication (Observer)

1. Implementation Strategy

To achieve absolute decoupling, the project implements the Observer Pattern using C# Events. The Domain layer remains entirely unaware of the visual representation; it simply broadcasts state changes via notifications. The View layer (Unity) subscribes to these events and independently decides how to trigger visuals, sound, or UI feedback.

2. Subject: Event Definition in the Domain Layer

Domain entities (e.g., Tower, Enemy) manage pure C# events. This ensures that the core gameplay logic remains uninterrupted and functional even in environments without a graphical engine.

Illustration from Tower.cs: The Tower logic handles cooldowns and target selection, then broadcasts the result without knowing who is listening.

public class Tower
{
    // Pure C# event, independent of Unity
    public event Action<TowerAttackResult> OnAttack;

    public void Tick(float deltaTime, List<Enemy> enemies)
    {
        var result = _attackStrategy.ExecuteAttack(this, enemies);

        if (result != null && result.IsSuccess)
        {
            // Broadcast the notification to all observers
            OnAttack?.Invoke(result); 
        }
    }
}

3. Observer: Listening and Responding in the View Layer

Unity components act as observers. When an event is triggered, the View executes performance-heavy visual tasks—such as spawning particles or playing audio—that the Domain does not need to process.

Illustration from EnemyView.cs: The View subscribes to logic events to trigger complex animations like parabolic knockbacks.

public void Initialize(Enemy enemy)
{
    _enemy = enemy;
    // Subscribe to the event from the Domain entity
    _enemy.OnKnockBack += HandleKnockBack;
}

private void OnDestroy()
{
    if (_enemy != null)
        // Critical: Unsubscribe to prevent memory leaks in Unity
        _enemy.OnKnockBack -= HandleKnockBack;
}

4. Reactive One-Way Data Flow

This mechanism facilitates a clean, reactive flow where data move in one direction:

  1. Domain: Processes logic -> Changes state -> Invokes Event (Action).
  2. View: Receives event -> Updates visuals/audio based on the new state.

Illustration from TowerView.cs:

private void HandleAttack(TowerAttackResult result)
{
    if (result.IsSuccess)
    {
        // Spawning visual effects only when the logic layer confirms an attack
        GameObject bullet = Instantiate(_bulletPrefab, firePoint.position, Quaternion.identity);
        bullet.GetComponent<ProjectileView>().Initialized(result);
    }
}

5. Technical Advantages

  • Optimized Performance: Eliminates the need for “Polling” (checking states in Update), significantly reducing CPU overhead on mobile devices.
  • Multi-Observer Support: A single event (e.g., OnEnemyDeath) can be observed by multiple systems simultaneously: EnemyView plays an animation, CurrencyService adds gold, and AchievementSystem tracks progress.
  • Resource Integrity: Proper unsubscription patterns in OnDestroy ensure that no dangling references remain when Unity objects are destroyed, preventing potential memory leaks.
