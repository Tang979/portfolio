Composition Root & Lifecycle Management

1. The Role of Composition Root

In a decoupled architecture, a Composition Root is the unique location in the application where the dependency graph is composed. In this project, the GameController (a MonoBehaviour) serves this purpose. It acts as the bridge that instantiates pure C# services and injects them into the necessary Unity components during the initialization phase.

2. Centralized Initialization Flow

Instead of having multiple scripts initializing themselves in an unpredictable order, the GameController enforces a strict, linear initialization sequence. This prevents NullReferenceExceptions caused by one service trying to access another that hasn’t been created yet.

Illustration from GameController.cs:

protected override void Awake() 
{
    base.Awake(); // Standard Unity initialization

    // Phase 1: Instantiate Pure C# Logic (Domain Layer)
    _pathfinder = new AStarPathfinder();
    _map = MapLoader.LoadMap(_mapJson);

    // Phase 2: Manual Dependency Injection
    _laneService = new LaneService(_map, _pathfinder);
    _enemyService = new EnemyService(_map, _laneService, _currencyService);
    _placementService = new PlacementService(_map, _pathfinder, _laneService);

    // Phase 3: Synchronize with Unity Infrastructure (View Layer)
    InitializeViews();
}

3. Lifecycle Synchronization

Managing the lifecycle of objects that do not inherit from MonoBehaviour requires manual updates. The GameController ensures that the Domain Layer stays in sync with Unity’s frame updates by forwarding the Tick signals.

Illustration of Update Forwarding:

void Update() 
{
    float deltaTime = Time.deltaTime;

    // Forwarding Unity's update loop to Pure C# services
    _enemyService.Tick(deltaTime);
    _placementService.Tick(deltaTime);
}

4. Controlled Disposal

Just as initialization is centralized, the cleanup process is also managed to ensure memory integrity. When a level ends or the game is closed, the GameController triggers the disposal of services to unsubscribe from events and clear cached data.

void OnDestroy() 
{
    // Explicitly clearing logic states when the Unity Scene is destroyed
    _enemyService?.Dispose();
    _placementService?.Dispose();
}

5. Technical Advantages

  • Predictability: Eliminates race conditions during game startup by defining a clear “Source of Truth” for initialization.
  • Single Responsibility: Other scripts (like TowerView or EnemyView) don’t need to worry about where their data comes from; they simply wait to be initialized by the controller.
  • Maintainability: Adding a new global service only requires a single line of code in the Composition Root rather than modifying multiple Prefabs or Singletons.
